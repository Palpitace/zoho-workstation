## 同步契约

首次运行先获取近期最多 SampleSize 个工单 ID，再通过 SQLite Reserve 冻结样本；详情拉取前已持久化名额。SampleSize 默认 50，禁止超过 50；MaxTickets=0 表示处理本轮全部候选，正数限制本轮详情数量，用于首批小样本检查。

Start 在 SQLite 中持久化一次完整同步的 batch_upper；分批、失败和重启都复用这个上界，直到全部完成。无水位、仍有未保存工单或之前有失败时，以冻结样本作为候选；其余轮次通过 Changed 查询固定 IDs 在“上轮水位减 Lookback”到固定 batch_upper 内的变化；Lookback 默认 24h。首次空部门查询没有工单时允许之后重试选样，不伪造工单。

所有候选先排除已在当前 batch_upper 之后检查且快照完整、无同步错误的工单。CheckedAt 记录最近一次成功或失败尝试的完成时间；缺失或不能解析时保守重取，并按尚未尝试处理。过滤后的候选按 CheckedAt 升序排列，同时间保持原顺序，再施加 MaxTickets 限制。失败仍需重试，但让更久未尝试的工单先获得机会；顺序依据在 SQLite 中保留，重启不会让连续失败的头几个 ID 永久阻塞后续工单。

每张工单独立保存。获取或清洗失败只记录 Failure，保留之前的数据。若新快照不完整且已有完整快照，保留旧完整快照；首次不完整快照可保存供查看，但同时记录失败，不能推进水位。

增量搜索受限后的固定 ID 回查遇到单票不可读、移出部门或无有效元数据时，zoho 将原 ID 作为待完整 Fetch 候选。同步器沿用相同的逐票校验与 Failure 路径，不保存其他部门的响应；单票错误不会阻塞其他候选，失败仍阻止水位推进。认证、网络及取消等全局错误不会降成成功。

Result.Fetched 是本轮成功完整保存数，Failed 是本轮失败/不完整数，Remaining 是过滤后候选中尚未尝试的数量。MaxTickets 造成的分批剩余不是失败，返回 nil error，但不推进水位。只有全部候选成功且完整才调用 Finish 把水位推进到固定 batch_upper，并清除该上界。失败记录和完成状态使用短暂独立 context，保证调用方取消后仍能记录失败；失败与取消保留 batch_upper，不推进水位。

合成测试通过公开 Run/Store 边界和 httptest 验证，不读取 .env 或真实工单：`go test ./internal/syncer`。原场景覆盖连续 MaxTickets=1 的初始与多候选增量分批、中间失败、SQLite 重启、最终水位提交及成功快照保护；一个参数化场景覆盖初始/增量 MaxTickets=3 时前 3 张持续失败、重启后其余 3 张仍能成功，以及失败最终恢复前水位不变；另一个小场景验证增量回查的 404/跨部门单票错误会持久记录、重启后另一固定工单可更新且范围/水位不变。设计简化检查：复用 checked_at、公平排序及现有 Fetch/Failure 处理局部元数据异常，不改运行编排，不增加字段、批次成员表、错误列表接口或重试队列。
