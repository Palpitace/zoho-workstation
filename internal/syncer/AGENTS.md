## 同步契约

服务传 StartTime 启用持续发现，首次及每个同步窗口从最新列表开始，仅接受创建时间不早于该时间的指定部门工单，没有累计数量上限；旧记录保留。StartTime 为零的 CLI sample 保留显式 SampleSize（1..50）初始采样入口。MaxTickets=0 允许 CLI 完成本轮候选，服务使用 SYNC_BATCH_SIZE（默认 9）；成功、失败及确认合并/删除/移出都占一次批次名额。

Start 持久化固定 batch_upper，未处理完候选、全局查询/存储错误、429 或取消均保留该窗口，不推进水位。成功保存或已持久记录单票失败/停止均代表该候选已处理；全部候选处理后推进到固定上界，失败仍独立保留，不能把水位解读为所有快照完整。

每轮先从冻结 IDs 排除 sync_stopped、当前窗口已完整读取和冷却中的失败；正常候选用 Changed 查询，Pending/不完整和到期失败直接 Fetch，不受增量时间窗限制。因此水位推进不会永久遗漏失败 ID。当前 batch_upper 后已尝试的失败即使冷却到期也不重复加入同批，只在下一窗口重试，避免大量持续失败拖住水位。错误的 checked_at 解析失败时保守重试；正常失败按 checked_at 至少间隔 5 分钟，跨重启保留。候选按最近尝试时间升序公平调度，不为重试新增队列表或时间配置。

每张独立保存。错误保留旧快照；新会话不完整时优先保留旧完整快照，否则保存部分证据并记录失败。HTTP 403/404、搜索缺失或缺部门不单独证明删除/移出。仅匹配 ID 和部门后 isDeleted=true、匹配 ID 且明确移出部门，或 Zoho 只读生命周期复核确认旧 ID 已合并/删除才调用 StopSync，保留此前快照并停止后续网络读取。

Result.Fetched 是完整保存数，Failed 是持久失败数，Stopped 是本轮确认合并/删除/移出数，Remaining 是尚未处理的本轮候选数（不含冷却重试）。失败持久化后仍返回安全错误；局部失败不拦截其他工单或水位。429 返回原限流错误供 app 等待，停止本轮后续请求。取消使用短暂独立 context 保存失败，不能提交批次水位。

验证：`go test ./internal/syncer` 使用合成 HTTP/隔离 SQLite，覆盖初始和增量分批/重启/重复更新、全局失败及取消水位保护，另参数化覆盖读取前/期间移出、403/404、不完整快照、独立冷却重试及历史保护。旧“任何单票失败都必须阻止水位”断言由 Issue #1 的明确新契约替换，未放宽取消或全局失败约束。

简化：沿用 sync_error/checked_at 保存重试义务，仅增加已确认移出的停止标记；不增加重试队列、任务表、轮次重置或配置选项。

Concurrency 默认 1（直接调用兼容）；服务/CLI 显式传入配置的默认 3，上限 5。每个并发小组只执行 Fetch，全部返回后由协调者串行 Normalize/保存；不并发访问同一工单或构造 SQL 写线程。429 立即取消同组请求，等待它们退出后结束本批，调用方遵守最大 Retry-After；仅被同组限流取消的工单保持待处理，不误记成单票失败并冷却 5 分钟。外部取消仍保留窗口和失败义务；剩余候选不会被游标跳过。无独立队列、无预取后续批次。

会话不完整的 sync_error 同时保留 Normalize/Fetch 生成的固定 warnings 原因码（例如 threadCount_mismatch）；即使保留旧完整快照，也能从详情错误看到本次失败原因，不包含正文或凭据。

合并生命周期确认返回 ErrMerged 时同样 StopSync，保存固定原因 ticket confirmed merged in Zoho，保留原快照和采样名额，后续不再重试。已停止 ID 仍不会自动复查或恢复；本次没有改为全部门扫描或新增目标工单。集成回归覆盖 404 + TicketMergedChild 确认后跨重启不重试；无证据 404 继续冷却。

Issue #5：每次 Run 最多请求一个25条列表页，发现页的全部身份/部门/创建时间/时间倒序校验通过后，工单ID与下一offset在同一个SQLite事务保存。discovery_cycle绑定可恢复batch_upper，discovery_start绑定配置起点；中断重启恢复相同offset，读页或写库失败不推进。短页或越过创建起点结束本轮发现；同一周期完成后其余详情批次不重复列表页，未发现完时Remaining额外含一个发现续页标记，阻止同步窗口提前完成。
新同步周期从offset0重新扫至创建起点，抵抗offset列表新增/合并/删除导致的位移，靠本地ID去重；位移可能使本轮暂时漏项，下一完整扫描补齐，不把created时间当稳定远端游标。不会只因已有ID/50条而停止发现。扫描从最新页到起点之间的总成本会随工单数增加，但每次Run只一个发现页、详情仍按MaxTickets/Concurrency有界；元数据增量查询按50个ID分组，403仍可能逐票读取元数据，不能声称全局固定请求量。
持续模式把已保存完整快照的modified_time传给ChangedKnown。搜索或单票元数据证明相同更新时间（按时间值比较，兼容UTC/偏移字符串）时跳过完整会话读取；身份/部门/删除等检查优先，异常仍走原Fetch/停止路径。不完整/失败项继续独立恢复。合成测试验证60条超过旧上限、时间边界、分页失败/重启、去重、新到工单、UTC等价时间不重复读会话。

起点之前已有快照保留展示且不打永久StopSync标记；服务候选循环排除能确认created_time早于StartTime的记录。已有记录时间未知时不能推断其过期，沿原同步流程恢复；CLI显式采样不受该服务日期规则影响。

并发恢复测试按首轮实际请求的 ID 推导未启动集合，不假定候选数字顺序；乱序输入仍须让全部未启动工单恢复完整快照，已取消失败的工单继续遵守独立冷却。
