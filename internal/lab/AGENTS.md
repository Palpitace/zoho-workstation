负责离线 FAQ 批次的快照、分组、回放节点与模型结果契约。
由 app 编排、store 持久化、analysis 调用固定 Python 入口。
不访问数据库或外部服务，不发布知识或回复客户。

| 名称 | 地位 | 功能 |
| --- | --- | --- |
| AGENTS.md | 目录约定 | 离线实验职责和输入隔离 |
| model.go | 数据契约 | 固定批次输入、调用与反馈历史、回复评估和知识修订 |

每批最多 50 张完整脱敏工单；学习、调优、留出按工单分组，不把同票不同节点分到不同集合。生成/评估只使用截止节点之前的公开已发消息，不读取当前状态、描述、整票总结等可能包含未来信息的可变字段。每次调用绑定输入 Hash、Schema 和模型，先保存 running 再发送。人工评分绑定具体回复调用，旧记录保留；仅后续明确启动的批次使用调优反馈。正式知识依旧需要人工发布。

| prepare.go | 输入准备 | 历史前缀、关联分组与污染知识排除 |
| prepare_test.go | 准备验证 | 后续/可变字段隔离与重复同组 |
| plan.go | 有限流程 | 单步推进、独立评估、候选检索及跨轮反馈 |
| plan_test.go | 流程验证 | 有限重试改写、留出隔离与机型/语言召回 |

学习集提炼可读完整公开会话，开发节点最多初稿加两次改写，留出各读原知识与固定候选各一次，不用于提炼或反馈优化。每步最多两次尝试，已成功复用。候选同一正式条目的多个修订以最后一份为准，旧候选仅保留历史。ValidationComplete 仅证明所有留出比较调用成功，不证明质量或业务效果。

Split 按稳定组分配，LinkGroups 合并用户声明的关联组并保留自动重复组。检索按历史原文确认机型边界，候选保留原语言客户报告节选；最多八块，候选最多四块。部分技术文档所有检索块均标只读，不允许替换整份。正式草稿继承完整来源链。

DevelopmentFeedback 保留原评分批次、调用和对应回复，最多每节点最近十条、128 KiB，旧记录不删除；留出反馈不进入下一轮。批次原输入与成功调用不可覆盖。更多使用与限制见 docs/offline-lab.md。
