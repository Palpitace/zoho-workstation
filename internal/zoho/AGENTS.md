## 限定 ID 的增量回退

Changed 首选 `/api/v1/tickets/search`，传入已冻结的最多 50 个 ID、固定部门及 modifiedTimeRange。仅该业务 GET 返回 HTTP 403 时切换为逐 ID 的 `/api/v1/tickets/{ticketId}` 检查；其他 HTTP、网络、认证或响应错误继续失败。搜索返回不在固定样本中的 ID 或其他部门也直接拒绝，不回退绕过边界。

403 模式只缓存在当前 Client 实例，使用原子标记；首次切换记录一次固定说明、HTTP 状态和样本数量，不含 ID、部门、正文、URL 或密钥。进程重启/新 Client 会重新尝试搜索。模式缓存不是权限升级，也不增加采样 ID 或遍历任何部门列表。

回退依据 OAS `Ticket.json` 的 Get Ticket（Desk.tickets.READ）和 ticketResponse 的 id、departmentId、modifiedTime。省略可选 include，不猜测字段投影参数。接口实际返回工单详情，客户端只提取上述元数据；每张验证返回 ID 和部门，用 RFC3339Nano 解析更新时间，按 `since <= modifiedTime <= until` 选择。OAS 旧示例有毫秒数字，而 schema 为时间字符串；当前遵循已有时间解析契约，不猜测未知格式。

单票元数据 404/410、无明确全局认证错误的 403、ID/部门不符或时间缺失/无效时，只把原本请求的固定 ID 纳入完整 Fetch 候选，不采信该响应、不添加响应中的其他 ID，也不伪造更新时间。Fetch 仍先严格校验 ID/部门，再读取会话；失败由 syncer 独立持久记录并冷却重试，保留旧快照；水位不再等待单票恢复。明确的 OAuth/Scope 错误、401、服务端错误、取消和网络错误仍使本轮整体失败。

每轮最多读取 50 个固定 ID 的详情（同一调用中重复 ID 去重），不由 Changed 获取 threads/comments，也不访问样本外 ID。搜索成功时也对结果缺失的固定 ID 用同一元数据路径复核：缺失本身不证明移出，404/403 仍交给 Fetch 和持久失败处理。代价是搜索受限或大量缺失时每轮约 N 次详情读取；这些响应可能包含比元数据更多的工单字段。没有本地版本比较，重叠回查窗口内的工单仍可能由 syncer 再完整 Fetch，不能声称避免了所有重复会话读取。同步水位及重启恢复仍由 syncer/store 决定。

## 验证与简化

复用一个 Changed 表驱动场景验证搜索成功、ID/部门边界、超过 50 拒绝、403 缓存回退、闭区间时间筛选、局部元数据异常仍只返回原 ID，以及全局 OAuth/Scope 和服务端错误整体失败。syncer 的小型集成场景另验证 403/404/不完整时其他固定 ID 仍能更新、水位推进及独立失败重启恢复。仅使用 httptest，不读 .env/data 或真实服务。设计简化检查：保持原 Changed 签名和具体 Client，局部失败复用现有 Fetch/Failure，不增加错误列表接口、store 依赖、权限探测服务、配置开关或队列。

## 部门停止与限流

Fetch 在详情开始及结束都校验返回 ID 和部门。只有匹配原请求 ID 且明确的非空数字部门不同才返回 ErrOutsideDepartment；身份不符、缺部门、HTTP 403/404 及线程计数不符都是普通错误/不完整。确认移出时返回空快照，不把新部门的响应保存为本地证据；syncer 保留历史并永久停止该保留 ID 的读取。搜索候选本身仍严格限定请求 IDs 和原部门。

HTTP 429 的 RetryAfter 只暴露等待时长，支持 Retry-After 秒数/HTTP 日期，无有效值默认 30 秒，长秒数不缩短为默认值、溢出保守饱和到最大可表示等待；不打印头、代理、URL 或响应正文。syncer 收到后停止当前批次，app 可取消地等待至少该时长。同步器可有界并行调用 Fetch，但单张工单内部分页/线程详情仍顺序读取；没有自动业务写入。

实测修正（2026-11-05）：指定失败样本有 isDeleted=true 且 threads 返回 404；Fetch 在前后两次详情验证时读取严格布尔 isDeleted，仅同部门明确删除返回 ErrDeleted，不依赖 404 猜测。另一样本 threadCount=2 而完整分页实际返回 3 条（不同 channel）；计数仅作为缺失下界，实取小于计数仍标不完整，多于计数不再误报。分页、内容截断、前后 modifiedTime 和部门一致性检查保留。原始第三方数据不修改。
