负责知识条目、文档片段和可追溯检索引用的最小数据契约。
由 store 持久化及筛选有效来源，app 提供脱敏输入并校验案例版本。
不访问数据库、外部模型，不把案例自动升级为正式 SOP。

| 名称 | 地位 | 功能 |
| --- | --- | --- |
| AGENTS.md | 目录约定 | 知识模型与检索边界 |
| model.go | 知识契约 | 条目分类、工单来源链、不可变 Markdown 版本、稳定引用及有界词面排序 |

Source ID 使用 `knowledge:<条目ID>:<块ID>`；条目内容不可就地覆盖，SOP 修改另建草稿，案例保留原工单和消息 ID。案例 SourceHash 由 app 对照当前输入，不能因检索命中而把过期案例当作最新来源。

检索以机型相容、词面命中为基础，正式 SOP 优先。机型不明时只使用通用 SOP，不借用其他机型案例；已知机型也不使用机型不明案例。英文按单词、中文按相邻双字匹配，不声称具备跨语言语义检索。每次最多 24 个完整片段、正文合计最多 64 KiB，不截断来源正文；无相关命中则返回空集合。


条目 `scope` 区分 technical、policy、reference；默认未分类资料为 reference。`SourceTickets` 记录派生工单并随版本继承，供离线实验排除学习/验证数据泄漏；`LabBatchID` 追溯离线提案。检索 Source 同步传递分类，使模型只能建议修订明确归类的技术知识。发布、恢复及历史读取由 store 负责，模型契约不自带数据库或版本服务。

## Markdown 与本地混合检索

具名 `Library` 绑定明确的 `DepartmentIDs`；分类属于一个库。`Entry.Markdown` 是唯一可编辑正文，`Blocks` 是派生的检索/引用视图。旧条目读取时从原块合成 Markdown 并设置 `markdown_migrated`，旧块 ID 和内容保持不变。新保存的 Markdown 版本重新派生块，历史引用仍定位原条目/块。

`MarkdownBlocks` 保留文档开头的适用条件，按最浅重复标题拆分，子步骤/表格不跨父问题拆开。每块最多 16 KiB，过长完整过程显式拒绝并要求整理，不裁剪。`CleanMarkdown` 只去除 font 导出样式、空标题；跨行标题恢复和非空 HTML 注释均记录复核标记，注释文字可见保留，不能把 OCR 当已确认事实。通用导入不根据中英文标题猜测同义；人工整理的双语问题可作为完整单条 Markdown 导入。

`ApplicableProducts` / `ExcludedProducts` 明确限制机型；含白名单或排除项时未知机型不使用此条目。部门过滤必须在召回前完成。`HybridSources` 独立按词面和余弦排序，用 RRF（常数 1，词面权重 2、语义权重 1）合并；只接收当前发布版本/内容 Hash/分块版本的向量。语义通道最高相似度须达到 0.40，启用后保留至少 0.35 的候选，均是过滤启发式，不是业务正确概率；需要实际检索集比较。无向量时沿用关键词召回。结果最多 24 块/64 KiB，不截断正文。

分块版本固定 `markdown-parent-v2`。1024 维持久向量由 store 校验；余弦计算拒绝非有限数值/零向量/维数不符。模型/分块标识在调用方选定并由存储查询严格过滤，不能用旧模型索引冒充新版本。


`ContextText` 在引用视图中附上明确适用/排除机型，不覆盖正文；词面及混合召回共用。离线实验先用历史前缀核对机型后再使用该视图，不能把条件与子过程拆散。


实际简化：机型判断统一复用 `Applicable`，移除词面召回中已被该函数覆盖的第二套 Product/未知案例判断；复用已有机型/案例/混合召回测试验证，没有另建策略接口或重复模型。


实际 FAQ 语料验证发现，24 个候选使用 RRF 常数 60 会过度偏向两路都勉强命中的片段；原始 Markdown 的不透明图片/下载 URL 也干扰向量召回。`EmbeddingText` 只为索引去除 URL 目标和 OCR 说明标签，保留可见链接/图片文本及原文条件，引用返回完整原证据。修改索引视图使分块版本升级 v2，旧向量不会被当作新表示。

词面过滤忽略通用英文疑问词；查询有至少三个实质词时要求至少命中两个，避免只因 How 或 Home 检索不相关 FAQ。显式 `error code` / 错误码查询须逐字完整命中错误码，未知码不能语义借用相近码步骤；普通查询不受代码门槛影响。阈值和权重由有限暂定检索样例比较选定，不代表通用准确率或人工金标。保持机型/部门过滤先行，向量无法覆盖授权或排除条件。


兼容性回归：已确认匹配 Product/白名单机型的资料，仍允许一项真实非机型技术词命中；机型本身永远不算相关性。否则长期会话中的多词查询会误丢弃明确的“某机型校准”SOP，导致其正式修订不能让相关建议过期。语义置信度作用于整个通道而非逐条强截断，防止可靠邻域中较低分的跨语言证据被排除。

本地真实 Qwen 测量：80 条私有 FAQ、12 个暂定开发问法，旧词面 Top1/Recall@3 为 7/12、9/12，最终混合为 8/12、10/12；事先另定的四问在首次检查时为词面 1/4、2/4，混合 2/4、3/4。两项无答案检查均返回空，未知/相近机型禁止命中为零。之后因原有合成和应用测试暴露阈值边界回归，对全部 16 问复查仍为 10/16、13/16；此时 16 问只称回归集，不再称未见留出。最初常数60的原始 Markdown 混合方案实际只有开发 6/12、7/12，失败结果和试验记录保留，没有改预期来源让结果通过。标签由资料初读暂定，未经用户人工校准；取消订阅、PC 蓝牙及 Beta 下载仍有漏召回，不能声称通用业务准确率。

原生ARM验收暴露固定0.45门槛对接近边界的有效同义候选过于敏感。采用0.40候选时，固定16题及无答案/机型回归均无损；增加原生合成余弦诊断，不改变预期来源，实际ARM结果仍由CI验证。
