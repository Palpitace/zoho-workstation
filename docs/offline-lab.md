# 离线 FAQ 实验

第一阶段用于内部模拟、评估和修订知识。不会向客户发送回复，不写入 Zoho，不接入企业微信。沿用现有 DeepSeek 配置，不需要新增 Key；Go 服务和随附 Python 环境必须运行。

## 使用

1. 先让当前部门工单同步完成，在知识库导入并审核发布 FAQ/SOP。选择分类：技术知识允许提出修订；售后政策只读；不确定的资料保留为只读参考。旧资料默认只读参考，可通过人工修订明确分类。
2. 打开侧栏“离线实验”，选择创建时间范围，默认从 2026-11-05 00:00 UTC+8 起，读取最近最多 50 张本地完整工单。不额外回填其他日期或部门；需要补齐数据时使用既有同步入口。
3. 勾选工单与已发布知识版本。相同首封客户正文自动同组；已知关联工单填写相同关联组。至少需要五组不同工单。作者、消息时间或修改历史不明确的节点不参与模拟。每票最多选首次客户消息及客服处理后的两次客户补充；这是保守的节点规则，不声称穷尽语义上的所有关键节点。
4. 保存后先预览学习／开发／留出分组，再手动启动。分组约 60%／20%／20%，按组而非消息划分；重复组大小可能使数量偏离 30／10／10。保存批次本身不会调用模型。
5. 批内依次提炼学习集技术知识，模拟开发节点、独立评估、最多两次改写，再在固定留出节点对比原 FAQ 与候选 FAQ。每一步最多两次尝试；失败保留，不无限优化。模型累计额度仍已关闭，这里的迭代边界仅针对手动实验。
6. 查看每个回复版本并打 1～5 分，可补充标签、建议或直接改写。评分不启动模型；旧回复、评分和修改全部保存。下一轮手动创建时保留同一批次输入和分组，只纳入开发节点的反馈，连同被评分的原回复；留出评分仅供审核。每节点最多带入最近十条、合计 128 KiB 的反馈，完整记录仍可查看。
7. 留出两组调用均成功返回后，技术候选可保存为知识库草稿。对比原文、适用条件、来源和模型评估，再明确发布。模型评分不是人工标准答案，也不证明真实解决率；未检索到适用候选时，两边可能使用相同知识。失败调用不能冒充验证完成。
8. 知识库支持版本历史、逐行差异、停用和“恢复为草稿”。恢复也生成新版本，必须再发布，原历史不覆盖。已被更晚修订取代的实验候选保留供查看，不能作为当前验证过的候选晋升。

暂停只阻止后续调用，正在执行的一次会保存结果。服务重启把未完成批次暂停，并将无法确认完成的调用标为中断；使用“继续批次”恢复，已成功步骤复用。模型或协议变化时拒绝原批继续，可从暂停批次创建新一轮。运行状态、调用结果、输入签名、实际返回模型、请求 ID 和用量（供应商有返回时）均持久保存；调用元信息和安全状态写入现有日志，不写正文或密钥。

## 输入与评估

回复与评估只接收截止节点之前的公开、已发送会话；不读取现在的标题、状态、产品字段、描述或整票总结。消息被修改且无法还原当时正文、时间顺序有歧义时不构造虚假的旧版本。完整脱敏会话仅用于学习集提炼或人工事后查看；后续真实客户反馈不能被当作对模拟回复的反馈。

每次评估使用独立上下文及单独 DeepSeek 请求，不带上一版评分或人工分数；检查事实、机型、诉求、重复失败措施、政策承诺，再检查语言。生成和评估使用同一家模型，错误可能相关，仍需少量人工复核。给客户的模拟正文跟随来信语言，内部理由和修订说明用中文。

知识在批次创建时固定，不读取之后自动积累的案例。当前自动案例以及源于本批工单的正式知识不能成为基线，避免把后续处理结果混进早期节点。派生草稿保留学习/开发集合与所用固定知识的完整工单来源链，后续批次继续隔离。独立文档缺少完整来源记录、同义或近似重复工单无法完全自动识别，需人工检查。

检索沿用本地机型及词面匹配，无向量数据库。机型按完整标识边界匹配，P1 不匹配 P10；候选附带原语言的客户问题节选改善跨语言词面召回，节选仅代表报告，不是已确认结论。每次最多八块，其中候选最多四块；不保证同义词或跨语言召回。部分技术文档在模型输入中降为只读参考，不能凭一个片段替换整份 SOP。候选只允许技术内容，不从个别退款、换货或保修处理推导政策。

自动校验可以检查结构和引用是否存在，不能证明每句话都被证据支持。正文仍采用现有脱敏器，不保证完全匿名。所有批次输入、输出和评分在忽略的 SQLite 数据库中，不提交 Git。

## 实现及验证

一个 `lab_batches` 表保存不可变输入与有界、追加式调用/反馈历史，不新增队列服务或长期 Agent。Go 编排，Python `lab.py` 通过固定 stdin/stdout JSON 完成 `reply`、`evaluate`、`propose` 单次调用，没有工具、Shell 或数据库权限。总结、案例、建议和离线实验共享一个 Bub 并发名额轮转，Jev 和同步仍独立。数据库输入上限 32 MiB、历史上限 128 MiB；超限暂停并提示改用较小批次，不静默截断证据。

`make test` 覆盖合成历史前缀、分组、留出隔离、独立评估、有限改写、重启、评分历史、政策保护和发布边界。`make build` 构建前端和 Go；`python scripts/check_lab_ui.py` 在具备 Playwright/Chromium 的验证环境运行合成页面操作，截图放在 `.cache/lab-ui/`。下载包随附 `lab.py`，沿用原生 Windows/macOS 工作流；本地 Linux 验证不代替原生 CI。
