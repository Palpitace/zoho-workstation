# 知识库使用与检索

知识库按名称管理，可绑定多个部门。绑定只影响知识检索，不改变 Zoho 工单同步范围。分类可新增、重命名，条目可移动分类。列表中的通用说明收进“帮助”，失败、草稿及过期信息继续直接显示。

## 导入、编辑与发布

1. 选择知识库，上传 ZIP 或多个 Markdown、TXT、DOCX、文字 PDF。单批上传最多40 MiB，解压最多64 MiB/250份文档，单文档最多10 MiB。
2. 集中预览分类、适用/排除机型、重复项和缺失内容。未知用途默认参考资料，可手动指定技术知识；整理清单保留明确的用途分类。原始文件私有保存在 `data/knowledge/originals`。ZIP 路径仅用于分类和关联素材，不按上传路径写入磁盘；重复路径拒绝导入。
3. 保存为草稿，或选择审核通过的条目批量发布。政策、OCR、日期条件、机型冲突默认不选中；发布需要明确确认。缺图资料必须补齐图片后发布。
4. 编辑器提供所见即所得、源码、预览模式，Markdown 为唯一正文。保存修订形成新草稿，不覆盖旧版本。查看差异后发布；恢复历史内容也产生新草稿。归档/替代不删除引用历史。
5. 支持 Markdown 和含本地图片的 ZIP 导出。编辑器可上传/粘贴本地图片。图片原样按内容Hash去重，不默认OCR；视频、软件下载等保留链接。

Vditor 资源与编辑器内核随前端构建发布，无公共CDN。页面渲染过滤脚本、iframe及不安全链接；图片只加载本机资源。Word/PDF 使用固定 MarkItDown 0.1.9 的字节流转换，禁用插件和云端识别。现有完整性检查仍保留：扫描页、图片、页眉/脚注及转换缺失会标记待处理，不能声称已完整提取。

原始Markdown保留本地信息；发送既有 DeepSeek 模型前再对来源正文、标题和产品做保守脱敏。自动脱敏并不保证完全匿名，特别是间接身份信息、图片文字和特殊地址格式。模型输入仍是待分析的数据，不是能覆盖系统规则的指令。

## 本次面单机 FAQ 整理

用户上传的14份资料沿用会员咨询、使用问题、按键步骤、故障排查、软件相关、驱动问题六个分类。整理产物保存在忽略的 `data/knowledge-prepared`，不加入源码或下载包。

整理采用两个开发子代理：技术整理者保留完整问题、双语内容与步骤；只读复核者检查来源、政策、冲突和图片数量。80个问题/流程单元覆盖全部14份来源，78组相邻双语标题合并，72个原图引用保留。机型例外、会员日期条件、内部升级与原文矛盾保留为待审核信息，不擅自确定正式政策。其语义正确性尚未经业务人员逐条确认。

导入预览已验证80个单元解析成功，引用图片已保存本地，没有发布条目。导入任务保存本地清单，可恢复预览及单项重试。整理包的 `_manifest.json` 是可编辑分类/来源提示，不是绕过审核或检索边界的授权。

## 本地语义检索

首次在“检索测试”启用本地模型，会下载约378 MiB模型，验证SHA256后安装；可查看进度、失败后重试。下载完成后知识/查询向量化不需联网。Bub生成回复仍使用已配置DeepSeek，这两种能力彼此独立。

- 模型：`PeterAM4/Qwen3-Embedding-0.6B-GGUF`，提交 `bb661aeeeafa4ff7303b5f5e1e80255efd6a513c`。
- 文件：`Qwen3-Embedding-0.6B-Q4_K_M-imat.gguf`，396474336字节。
- SHA256：`4d0f2e6e4132e96a0a0eac04cebfd11ff08cee89d3128aba6b276ae06f808c30`。
- 推理：官方稳定 llama.cpp v0.9.0，提交 `cd959bae99ff4bed22bef2604f45241c09bbb8c8`，源码归档Hash固定在打包脚本。
- CPU、last pooling、1024维L2归一化，查询加英文检索指令。Go直接管理子进程、回环地址、临时内部凭据、取消和关闭。用户无需另开模型软件。

检索先过滤知识库/部门和机型适用条件，再进行关键词与余弦相似度召回，用RRF合并。机型未知时不使用限定或排除机型的步骤。命中返回完整问题及适用条件，不把步骤与前提拆散；相似度仅是排序信号，不是事实概率。找不到来源时不能编造回答。

Go保存SQLite中的向量，按条目版本、内容Hash、模型和分块版本匹配，仅为已发布内容建索引。分块/索引版本为markdown-parent-v2；向量输入去除网址目标，引用仍保留完整Markdown。查询指令版本单独纳入缓存签名。进程每5秒检查待索引内容。业务工单查询向量在当前Bub总结成功后缓存，状态查询不启动推理；新缓存就绪后按来源变化判断建议是否过期。模型不可用时，未缓存的新查询使用关键词检索，界面集中显示降级与索引进度。草稿/过期索引不会冒充正式知识。

离线实验继续固定知识快照和历史节点，只用节点之前的机型证据；正式库授权被撤销时，不允许据旧批次新建后续实验。已完成历史记录不改写。离线实验的固定快照仍使用确定性关键词排序，避免后台新索引改变既有对比输入。

## 运行与验证

源码开发先执行 `python scripts/build_embedding.py`（构建机需CMake和C++编译器），便携包已包含程序。前端及Python依赖使用现有锁文件；不用安装Node生产服务、Dify、LangChain或向量数据库。

`go test ./...`、Python合成契约、前端类型/构建与文档检查覆盖基本功能。`VERIFY_LOCAL_EMBEDDING=1 go test ./internal/embedding -run TestNativeRetrieval -v -timeout=30m` 显式下载固定模型并做真实CPU检索检查，无生成模型收费调用。GitHub Actions在Windows x64、macOS Intel/Apple Silicon运行该验证并打包；三平台已在[原生构建42581051574](https://github.com/Palpitace/zoho-workstation/actions/runs/42581051574)通过，包括实际解压包的图文编辑；对应代码提交为10c5923。

检索比较使用固定中英文/同义问题、机型例外和无答案问题。来源推导的暂定预期不等于业务人员标注，测试通过不代表已证明生产准确率。

参考：[Qwen官方模型说明](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)、[量化来源](https://huggingface.co/PeterAM4/Qwen3-Embedding-0.6B-GGUF)、[llama.cpp](https://github.com/ggml-org/llama.cpp)、[MarkItDown](https://github.com/microsoft/markitdown)、[Vditor](https://github.com/Vanessa219/vditor)。

### 实测与限制

初始完整FAQ对照未通过：12条暂定有答案问题，旧关键词首位7/12、前三9/12，初始等权RRF为6/12、7/12。保留此失败结果，没有改动各问题预期来源。实际消融去除了索引中的不透明网址，随后在同12题上选择适合小库的RRF常数1、关键词权重2/向量权重1，并移除泛化问句词；多关键词查询要求至少两词命中，显式未知错误码不套用相近错误。该候选首位8/12、前三10/12；两条无答案问题为空，机型排除仍通过。尚不能宣称所有问法都能正确排序。

另一个6题合成跨语言集，原“每题必须首位正确”的诊断仅5/6通过（关键词3/6）。用户验收要求是提高相关资料召回，因此正式回归同时检查每题正确来源在前三、首位汇总改进、机型边界与无外网重启；保留原首位失败记录及预期来源，不将测试通过表述为100%首位准确。另4个暂定问题首次独立检查关键词首位1/4、前三2/4，混合2/4、3/4；随后修复已知合成回归，16题一起复查，最终关键词8/16、11/16，混合10/16、13/16。此后16题均称回归集，不再称未见留出。最终合成6题正确来源前三6/6、首位5/6。详细过程见PROGRESS.md。没有人工标准答案或生产效果证明。
