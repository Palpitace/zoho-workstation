# 案例知识与内部排查建议

Bub 保留当前工单的事实总结，另外自动整理历史案例，并结合已发布 SOP 为工单生成内部排查建议。不会自动回复客户、修改 Zoho 工单、改变同步范围或发企业微信消息。Jev 仍只读取当前事实总结，不接收历史案例或建议。

## 使用

1. 启动新版服务后，完整同步且在现有时间范围内的工单会依次进行事实总结、案例提取。案例保留问题、客服措施、客户是否确认执行以及实际效果，能够跳回原工单和消息。只有客户来信时也可积累问题案例，不编造客服步骤。
2. 在侧栏“知识库”导入 Word **DOCX**、包含可提取正文的 PDF、UTF-8 Markdown/TXT。填写适用机型；留空表示通用，发布前必须确认该适用范围。导入仅在本地解析，显示为待确认草稿。核对提取正文、来源位置、条件和步骤后点击“确认发布”，才会进入建议检索。
3. 工单详情的“参考排查建议”自动给出至多三项建议，显示需要补充的信息、冲突和引用。点击来源跳到对应知识版本/文档位置；当前工单消息引用支持展开定位与返回。缺少适用来源时等待资料，不为了凑建议调用模型。

历史案例可直接作为**效果有标记的参考**。客服建议不代表客户执行；工单关闭、无人回复、内部采纳或模型调用成功都不等于故障已解决。案例内容仍是模型提取，引用和角色校验不能证明所有语义正确。

“整理为 SOP 草稿”将案例问题、步骤和效果生成可编辑的审核底稿；它不是自动确认的标准流程。用户检查、补充适用条件、注意事项和结束条件后再发布。修订已经发布的 SOP 会创建新草稿；新版本发布前旧版继续生效，发布时原子替代旧版。停用保留历史及引用，不删除证据。

## 资料与提取限制

- 单文件最多 10 MiB，提取正文最多 256 KiB、4096 个位置块，每块最多 8 KiB；超限应按章节拆分，不静默截断。
- PDF 保留页码，DOCX 保留段落/表格位置，Markdown/TXT 保留行位置。长块使用明确的 part 编号。
- 不支持旧 `.doc`、加密 PDF、OCR。扫描页、嵌入图片、不能提取的页眉/脚注等会标为不完整并拒绝导入；请提供完整文本版。首版也可能拒绝只有装饰图片/页脚的文档，以免漏掉图示操作或限制条件。
- 文本抽取可能改变 PDF 阅读顺序或复杂表格布局。发布前必须核对预览；文本能解析不等于内容完全正确。
- 相同文件内容去重。重新上传同一文件却修改标题、机型或替代版本时，服务明确提示通过已有条目的修订草稿操作，不静默忽略修改。
- 原始文档在忽略的 `data/knowledge/` 下私有保存；提取内容在脱敏后存入 SQLite。当前脱敏器检查明显邮箱、电话和带标签的姓名/地址，但不保证完全匿名；独立文档没有工单联系人目录，无法识别所有未标注姓名或专有敏感信息。导入预览时检查这些内容，再发布给模型使用。

## 检索、版本与运行

知识条目及来源位于同一 SQLite，数据库仍只由 Go 访问。检索按机型相容性和正文关键词进行，优先已发布 SOP；它不是语义搜索，也不能保证跨语言召回。同义词或英文工单/中文 SOP 不匹配时，可在 SOP 中加入实际错误码、常见原文和机型。当前检索最多取 20 个候选、排除过期案例后保留至多 5 个来源；大量失效来源可能使本轮没有召回，不能解释成没有相关经验。

已知机型不借用其他机型案例；未知机型仅使用通用 SOP。Zoho 产品缺失时，可以使用当前案例从引用证据逐字提取的机型。固件、系统及操作前提仍需核对。模型接收的是选中片段，不能假定未提供的章节已经核实；缺少前提时应先查看完整 SOP 或补充信息。

案例来源签名包含当前会话、总结、Schema/模型及案例内容。同输入重提取修正了案例时，生成新的知识内容版本；相同内容不因请求 ID 改变而重建。旧会话结果不能覆盖新会话的案例。被人工停用的相同内容不会自动复活。

建议使用当前会话和选中知识版本生成输入 Hash。来源更新、停用或原工单变化时，受影响建议标过期，前端不把旧建议作为当前操作依据；其历史记录保留。未发布的草稿不改变当前建议。知识来源失效不改变原事实总结或 Jev 评估。

总结、案例、建议共享一个 Bub 模型并发名额并轮流执行；Jev 保留独立名额。复用现有 90 秒超时、1～30 分钟自动退避和重启恢复，任务失败不阻止同步和查看。不新增供应商、密钥、服务、向量数据库或运行时工具。已有 `ENABLE_BUB` 同时控制三类 Bub 调用；新增任务会产生配置供应商的模型费用，仍遵守当前已取消累计请求额度的设置，成功版本复用。

运行需要随附 Python 环境。新增固定依赖为 `python-docx==1.2.0`、`pypdf==7.0.0`，传递依赖及完整版本见 python/uv.lock。现有 Bub/Republic 版本保持不变。源代码安装沿用 `uv sync --project python --locked --no-dev`；下载包显式包含知识和文档入口。

## 依据、验证及回退

两份讨论中采用的是“证据保留、经验分级、人工确认正式规则”，没有把历史工单称为 Agent 工具轨迹，也没有实现模型训练、自动改 Prompt、长期会话记忆或自主执行平台。独立案例与建议复用现有运行记录，比建立第二套任务系统更容易恢复和检查。

官方接口依据：[Bub](https://bub.build/)、[python-docx](https://python-docx.readthedocs.io/en/latest/)、[pypdf 文本抽取限制](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。2026-11-09 核对解析器稳定包信息后锁定；未升级既有 SDK。

本轮验证仅使用合成数据、Mock 和本地解析器，覆盖证据角色、引用、草稿隔离、版本替代、纠正案例、旧来源排除、持久性及界面主链路。真实历史资料的提取质量、检索召回与建议效果尚未人工验收，不报告准确率或成功率。

数据库变更只新增知识表/索引，扩展原 ai_runs.kind；不重写既有工单或分析结果。回退应用版本可保留数据库中新表和记录；不要删除运行数据。生产部署及 Windows/macOS 原生下载包仍需相应发布流程验证。
