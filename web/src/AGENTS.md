使用 hash 导航保留浏览器前进/后退，不额外安装路由或状态管理库。查询与详情请求采用 AbortController；旧请求不得覆盖新选择。工单与分析结果独立读取，analysis 响应中的 Jev/Bub 分别保留自己的状态，AI 读取失败不阻塞会话展示。全局刷新只读取本地 API，不触发 Zoho 同步。

同步和两个模型操作分别保存提交中、错误及受理提示；依后端运行状态和开关禁用对应按钮，受理不等于成功。CSRF 值仅在内存和 POST 头。5 秒可见页面轮询先读 status，再刷新列表或详情，不以全局统计变化为前提；重新可见立即补查。不并行、不自动 POST、不重置调用统计，不提前应用尚未提交的筛选。卸载停止轮询并取消所有请求。

详情使用独立返回的 TicketRecord，同步错误和 pending 状态不从当前筛选列表推导。列表使用服务端全量 filters 构建五列 Combobox，选择后即时组合查询，轮询复用已应用筛选。列表只负责查询与导航，不成为详情状态的第二来源。

用户已关闭累计请求额度，App 不按请求次数禁用重新评估/总结；保留功能开关、运行中和未保存工单等必要禁用条件。

搜索栏保留独立草稿和已应用的关键词/字段/日期；刷新、轮询、表头选择均不提交草稿。五列表头和历史开关立即查询，清除恢复默认条件。App 统一生成时间边界和查询参数；Jev waiting_for=bub 时阻止重复手动提交并显示等待理由。

Issue #6：refresh 统一等待 status、详情和 analysis 的实际请求完成，不再使用 revision/effect 二次触发。首次无内容显示加载，已有内容时保留正文/结果，顶部固定宽度状态和旋转图标反馈，遵守 reduced motion。Promise.allSettled 独立处理失败端点、保留成功内容并提示旧数据；同一 AbortController 隔离新查询/导航，顶部手动刷新处理中合并重复点击，静默轮询不叠加请求。
