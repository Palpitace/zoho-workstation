所有工单正文使用 Svelte 文本插值，禁止 {@html}。附件只显示名称、类型及大小，不使用其 URL 下载或预览。API 报错不回显原始响应；POST 仅展示服务约定的安全 error 字段。

source=comment 不自动等于内部：结合 visibility 标记备注。mixed_authors=true 显示混合发言者，不把整段聊天归为单一客户。消息 DRAFT/FAILED/PENDING 和 is_description_thread 保留可见标记。角色未知不按方向猜测。

Jev 只展示评估枚举，隐藏模型/Schema/输入 Hash 等结果来源，不展示未校准的 confidence/probabilities；缺字段和 unknown 显示未知，no_explicit_clue 不等于低风险。当前情绪 unknown 或缺失时，情绪强度显示“待确认”，避免低强度暗示已知情绪；仅作展示，不改变模型原始结果。

Jev/Bub 分别展示 current、success 和 stale。当前失败保留已有成功结果，旧输入或旧配置结果明确标记过期；无成功结果显示待处理或失败，不生成假数据。Bub v3/v4/v5/v6 仅展示非空 device_info/customer_feedback/support_responses 三段，分别对应客户设备信息、客户反馈总结、客服回复或给予的排查；不输出缺失栏目或旧版强制下一步。旧 v1/v2 成功结果保留在 API/数据库，页面提示重新总结，不把混合旧字段重命名为新分类。

current.status=invalid 是本地输入无法处理，显示“无法评估/总结”和具体错误，不显示为待处理，也不假称已发模型请求；仍保留已有成功结果。Record.ai.status 已由后端将 invalid 统一为 failed。

Bub 每条事实保留 message_ids 引用；来自产品/描述字段的设备原文可无消息引用，显示“工单字段”。模型结果来源元数据不在页面显示但继续保存。引用通过当前会话精确匹配唯一消息，点击后打开目标消息的折叠祖先、原地滚动并聚焦消息，不改变 hash 路由或重新请求数据。旧结果引用缺失、ID 重复时显示不能定位原因，不随意跳到第一条。消息正文仍使用文本插值。独立分析读取失败不影响工单正文。

评估和总结各提供一个重跑入口，操作回调由 App 处理；组件只显示受理、错误或禁用原因。列表使用后端内嵌 AI 状态，不增加 N+1 查询；priority/emotion 缺失或未知显示未知，automatic_eligible=false 的 pending 标明等待同步，不暗示正在处理；已停止项标已停止。运行页显示后端持久化调用计数与各能力数量，并明确请求额度限制已关闭；不显示分母上限、预算耗尽标签或重复执行次数判断。

sync_stopped 优先显示停止原因：明确删除显示“Zoho 已删除”，其余显示“已停止同步”，详情区分 Zoho 已删除和移出配置部门、仅保留历史快照，不当成临时失败或当前事实。无历史快照也显示停止原因。普通 sync_error 显示等待重试及至少 5 分钟间隔；快照不完整单独提示。

详情顺序：紧凑工单信息（Card size=sm，长描述单独折叠）→ Jev → Bub → 沟通记录。沟通记录整个区域默认关闭，按 created_time 倒序，时间无效的排在最后，同时间保留原相对顺序；排序只对页面副本进行，不改模型输入/存储顺序。切换 ticket.id 重置折叠，引用可自动展开。仍使用原生 details/summary，无新增 UI 库或设计系统。

点击 Bub 消息引用后显示右下角“返回总结”按钮，返回刚才的引用并恢复键盘焦点；若引用已被刷新移除，则回到总结标题。返回后隐藏，切换工单通过 key 重置引用导航状态；不修改 hash 路由、不重新请求接口。Jev 移除用户指定的优先级/风险说明注脚，未知及失败状态仍按原规则显示。

Bub v4 中仅引用单条 unknown 且非 mixed_authors 消息的反馈标为“来信原文 · 作者未确认”；内容是否逐字摘录由 Go/Python 校验，页面不推断身份。运行状态显示后端实际批次/并发值，旧后端缺字段时不编造默认值。

列表默认隐藏 sync_stopped，勾选“显示已合并、删除或移出部门的历史工单”可查看；通过 show_history 查询已有最多 50 个样本，不改 Store.List 的同步/统计消费者，也不删除缓存。合并仅匹配固定 ErrMerged 原因，显示“已合并”，详情声明历史快照；删除不凭人工推测改成合并。搜索缺失或读取失败的工单不会隐藏。

沟通背景：客户浅蓝、客服浅绿；source=comment 或 visibility=private 优先浅黄；混合发言者与未知作者为中性灰，不按方向猜角色。保留角色/备注文字标记及深色配色，不只依赖颜色识别。

Bub 标题为“工单汇总”。v5 的客户反馈/客服处理各是零或一份综合摘要，可引用多条消息；设备信息仍可多项。旧 v3/v4 多条结果只作为过期历史保留，须重新总结才生成整单汇总；前端不把旧消息摘要简单拼接成新结果。

Jev 列表拆为情绪、优先级、问题分类，分类复用服务端 category，未知/过期不展示旧分类作当前结论。AI 列每个能力一行，名称固定宽度、一个不换行状态徽标；stale 与 pending/running/failed 合并显示待更新/更新中/更新失败，失败原因或过期解释放 title。两能力保持独立，不强制对齐其业务状态。

状态、产品、同步、情绪、优先级五列表头使用 FilterCombobox，触发器仅列名和箭头；已选列名加下划线，选中值仅在弹层/提示中显示。Popover + Command 为官方 shadcn 组件，弹层含搜索、全部/选项、勾选与全量计数；选择后关闭。工单列无搜索框或筛选图标。
顶部单行可换行组合搜索提供全部字段/标题/号码/ID/产品、关键词、日期字段和起止日期，Enter 或查询提交。表头立即应用但不提交搜索草稿；清除重置搜索草稿及已应用条件、五列表头和历史开关。空结果提示按已应用条件判断，不受搜索草稿影响；无筛选且无结果不擅自断言尚未同步。日期按浏览器本地时区转换为 [起始零点,结束次日零点)，日期不合法由表单和后端拒绝。未知首次来信不匹配日期范围。
标题仍跳本地详情，真实工单号链接继续使用安全 Zoho URL；前端不推测缺失号码/链接，不读取正文来猜机型。

流水线：Bub 先总结，Jev 后评估。AIStatus.waiting 优先显示“等待总结”；详情 AnalysisView.waiting_for=bub 时显示等待并禁用手动 Jev。旧结果保留并标过期，Bub 失败不阻止查看。运行状态页说明依赖顺序。

Issue #3：列表耗尽徽标简写“需重试”，title 给出“自动重试已耗尽”、最近失败时间及是否本次启动前的历史失败；详情同样显示，Jev 等待具体原因独立呈现。RunStatus 显示启动时间、耗尽数量、已确认待开始数，基于 status.retry_candidates 打开确认区，提交固定的 ticket_id/run_id 副本；打开/取消不发送请求。确认说明每张一次、费用及 Bub 成功后 Jev 自动接续，错误和受理消息不会被轮询清除。组件卸载取消未完成 HTTP，已经受理的后台批次不会因离开页面撤销。api.postAction 支持可选 JSON body，保留 409 安全原因。

Issue #7：TicketDetail 优先展示 message_segments[source:id]，缺少派生字段时展示完整 body。MessageBody 只使用文本插值和原生 details/summary，引用默认独立折叠，键盘可操作，浏览器暴露展开状态；嵌套引用递归显示。Bub 消息引用只提供消息 ID，因此跳转时展开目标消息内全部引用，避免引用证据藏在折叠区，浮动返回入口不变。刷新同一消息保留原生展开节点；原始 HTML 永不注入。Bub invalid_summary 显示中文证据校验失败说明和原有安全原因。

当前重试规则替代 Issue #3 耗尽显示：失败有 next_retry_at 时显示“等待重试”及计划时间，运行页显示退避策略和 retry_waiting 数量。用户可确认立即重试以跳过当前冷却，失败仍自动按间隔继续。运行页显示创建起点、持久发现进度、批次剩余、下次调度和停止记录数量，不再称固定样本。

## 知识与独立内部建议

KnowledgePage 复用现有灰阶变量和 shadcn Input/Button/Badge。资料导入只创建待确认草稿，展示解析后的全部文本和页/段块定位，用户点击“确认发布”后才生效。编辑始终另存新草稿，不覆盖已发布内容。案例可以整理为 SOP 草稿，历史工单/消息和被替代版本继续可点击查看；资料正文只做文本插值，不执行 Markdown/HTML。

TicketAdvice 位于事实总结之后、沟通记录之前，GET /api/tickets/:id/knowledge 的 case/advice 状态与 Jev/Bub 分离；仅当前成功结果显示建议，stale 结果不作为当前方案展示。建议显示步骤、理由、待补信息、冲突和准确来源。没有当前有效来源时显示 waiting_reason；手动重跑走原受保护 analysis/advice 入口，不自动 POST。所有知识写请求携带内存 CSRF 令牌，上传使用 multipart FormData，JSON 草稿使用独立契约。

建议组件每 5 秒在可见页面读自己的轻量状态，避免重叠，卸载取消轮询和请求；知识页由 App 的现有刷新周期驱动。编辑草稿不会被轮询覆盖。来源链接使用 #/knowledge/<id>?block=<块ID> 和 #/tickets/<id>?message=<消息ID>，仅在唯一匹配时展开并定位。

简化检查：未增加路由库、状态管理、编辑器或第二组件库；页面用纯文本预览/编辑和原有 hash 导航。人工发布是独立按钮，导入、编辑和保存均不会隐式发布。

已用合成 API 浏览器验证：导入仅生成草稿、明确点击发布、新草稿保留旧发布状态、建议到文档块/原工单消息的跳转、返回建议、过期步骤隐藏，1366×900 与 390px 布局无横向溢出或脚本错误。验收脚本及截图位于忽略的 .cache/knowledge-ui，未读取真实资料或调用模型。

Issue #9：API task_state 优先决定列表/详情徽标，冷却期间只显示等待重试，截止已过显示待执行；历史错误保留。RunStatus 的 Bub 区块按任务统计总结/案例/建议，展示活动工单、运行秒数和可展开的重试详情；计数明确不是工单数。429/HTTP错误/响应格式错误有独立说明，旧上游错误注明诊断缺失。详情的全局槽占用提示为其他任务，不等同于当前任务执行。

运行状态根据 sync_recent_limit 显示“按创建时间滚动最新50张”，避免把日期起点误显示为当前范围；列表及任务统计使用后端已过滤数据。

Issue #10：SystemStatus.sync.recent_confirmed 区分待确认缓存与已确认空范围；RunStatus显示缓存标签，并按last_sync_batch.stage区分选取和详情失败。

Issue #11：AIState/AnalysisView携带retry_blocked；failureHint显示连续证据失败的停止原因和手动重新总结入口说明，不再给出自动重试时间。沿用manual标签和既有操作，不新增配置页面。
