所有工单正文使用 Svelte 文本插值，禁止 {@html}。附件只显示名称、类型及大小，不使用其 URL 下载或预览。API 报错不回显原始响应；POST 仅展示服务约定的安全 error 字段。

source=comment 不自动等于内部：结合 visibility 标记备注。mixed_authors=true 显示混合发言者，不把整段聊天归为单一客户。消息 DRAFT/FAILED/PENDING 和 is_description_thread 保留可见标记。角色未知不按方向猜测。

Jev 只展示评估枚举，隐藏模型/Schema/输入 Hash 等结果来源，不展示未校准的 confidence/probabilities；缺字段和 unknown 显示未知，no_explicit_clue 不等于低风险。当前情绪 unknown 或缺失时，情绪强度显示“待确认”，避免低强度暗示已知情绪；仅作展示，不改变模型原始结果。

Jev/Bub 分别展示 current、success 和 stale。当前失败保留已有成功结果，旧输入或旧配置结果明确标记过期；无成功结果显示待处理或失败，不生成假数据。Bub v3/v4/v5 仅展示非空 device_info/customer_feedback/support_responses 三段，分别对应客户设备信息、客户反馈总结、客服回复或给予的排查；不输出缺失栏目或旧版强制下一步。旧 v1/v2 成功结果保留在 API/数据库，页面提示重新总结，不把混合旧字段重命名为新分类。

current.status=invalid 是本地输入无法处理，显示“无法评估/总结”和具体错误，不显示为待处理，也不假称已发模型请求；仍保留已有成功结果。Record.ai.status 已由后端将 invalid 统一为 failed。

Bub 每条事实保留 message_ids 引用；来自产品/描述字段的设备原文可无消息引用，显示“工单字段”。模型结果来源元数据不在页面显示但继续保存。引用通过当前会话精确匹配唯一消息，点击后打开目标消息的折叠祖先、原地滚动并聚焦消息，不改变 hash 路由或重新请求数据。旧结果引用缺失、ID 重复时显示不能定位原因，不随意跳到第一条。消息正文仍使用文本插值。独立分析读取失败不影响工单正文。

评估和总结各提供一个重跑入口，操作回调由 App 处理；组件只显示受理、错误或禁用原因。列表使用后端内嵌 AI 状态，不增加 N+1 查询；priority/emotion 缺失或未知显示未知，automatic_eligible=false 的 pending 标明未纳入自动分析，不暗示马上会处理。运行页显示后端持久化调用计数与各能力数量，并明确请求额度限制已关闭；不显示分母上限、预算耗尽标签或重复执行次数判断。

sync_stopped 优先显示停止原因：明确删除显示“Zoho 已删除”，其余显示“已停止同步”，详情区分 Zoho 已删除和移出配置部门、仅保留历史快照，不当成临时失败或当前事实。无历史快照也显示停止原因。普通 sync_error 显示等待重试及至少 5 分钟间隔；快照不完整单独提示。

详情顺序：紧凑工单信息（Card size=sm，长描述单独折叠）→ Jev → Bub → 沟通记录。沟通记录整个区域默认关闭，按 created_time 倒序，时间无效的排在最后，同时间保留原相对顺序；排序只对页面副本进行，不改模型输入/存储顺序。切换 ticket.id 重置折叠，引用可自动展开。仍使用原生 details/summary，无新增 UI 库或设计系统。

点击 Bub 消息引用后显示右下角“返回总结”按钮，返回刚才的引用并恢复键盘焦点；若引用已被刷新移除，则回到总结标题。返回后隐藏，切换工单通过 key 重置引用导航状态；不修改 hash 路由、不重新请求接口。Jev 移除用户指定的优先级/风险说明注脚，未知及失败状态仍按原规则显示。

Bub v4 中仅引用单条 unknown 且非 mixed_authors 消息的反馈标为“来信原文 · 作者未确认”；内容是否逐字摘录由 Go/Python 校验，页面不推断身份。运行状态显示后端实际批次/并发值，旧后端缺字段时不编造默认值。

列表默认隐藏 sync_stopped，勾选“显示已合并、删除或移出部门的历史工单”可查看；本地过滤已有最多 50 个返回项，不改 Store.List 的同步/统计消费者，也不删除缓存。合并仅匹配固定 ErrMerged 原因，显示“已合并”，详情声明历史快照；删除不凭人工推测改成合并。搜索缺失或读取失败的工单不会隐藏。

沟通背景：客户浅蓝、客服浅绿；source=comment 或 visibility=private 优先浅黄；混合发言者与未知作者为中性灰，不按方向猜角色。保留角色/备注文字标记及深色配色，不只依赖颜色识别。

Bub 标题为“工单汇总”。v5 的客户反馈/客服处理各是零或一份综合摘要，可引用多条消息；设备信息仍可多项。旧 v3/v4 多条结果只作为过期历史保留，须重新总结才生成整单汇总；前端不把旧消息摘要简单拼接成新结果。
